# Shortly URL Shortener API

The Shortly backend is a REST API built with Express. It validates destination URLs, creates and stores short codes in Supabase PostgreSQL, lists and deletes saved links, and redirects visitors while recording successful clicks.

The API currently has no authentication. Its routes and database policies are public; see [Access considerations](#access-considerations).

## Technologies

- Node.js 22 or later
- Express 5
- Supabase JavaScript client with Supabase PostgreSQL
- dotenv for loading local environment variables

## Backend structure

```text
backend/
├── index.js          # Express application, API routes, and redirect handling
├── schema.sql        # URLs table, RLS policies, and click-tracking function
├── package.json
├── package-lock.json
├── .gitignore        # Excludes node_modules/ and .env
└── README.md
```

Create `backend/.env` locally for configuration. It is not a committed project file.

## Prerequisites

- Node.js 22 or later and npm
- A Supabase project
- The Supabase project URL and anon/publishable API key

## Install and configure

From the project root, install the backend dependencies:

```bash
cd backend
npm install
```

In the Supabase SQL Editor, execute [`schema.sql`](schema.sql) to create the table, access policies, and click-tracking function.

Create a `.env` file in the `backend/` directory:

```env
SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
SUPABASE_KEY=YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY
PORT=3000
BASE_URL=http://localhost:3000
```

`SUPABASE_URL` and `SUPABASE_KEY` are required. `PORT` defaults to `3000`. `BASE_URL` defaults to `http://localhost:<PORT>` and is used to construct the `shortUrl` returned by the API. Trailing slashes in `BASE_URL` are removed before a short URL is built.

Use the anon/publishable key with the policies in `schema.sql`; do not put a service-role key in this file. Keep `.env` private and never publish real project credentials.

## Run locally

Run these commands from `backend/`:

```bash
# Development; restarts the server when files change
npm run dev

# Normal start
npm start
```

The default server address is `http://localhost:3000`. The startup message displays the configured `BASE_URL`.

## API

All responses with JSON bodies use `application/json`. No authentication is required by the implemented routes.

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/` | Health check |
| `POST` | `/api/urls` | Validate and create a short URL |
| `GET` | `/api/urls` | List stored URLs, newest first |
| `DELETE` | `/api/urls/:shortCode` | Delete a stored URL |
| `GET` | `/:shortCode` | Increment clicks and redirect to the destination |

### Health check

**Request**

```http
GET /
```

**Response — `200 OK`**

```json
{
  "message": "URL Shortener API is running!"
}
```

### Create a short URL

**Request**

```http
POST /api/urls
Content-Type: application/json
```

```json
{
  "longUrl": "https://www.example.com/"
}
```

**Response — `201 Created`**

```json
{
  "message": "URL shortened successfully",
  "longUrl": "https://www.example.com/",
  "shortCode": "a1b2c3d4",
  "shortUrl": "http://localhost:3000/a1b2c3d4"
}
```

The short code and URL shown are examples; actual codes are generated by the API. An invalid `longUrl` returns `400 Bad Request`:

```json
{
  "error": "Invalid URL"
}
```

Database write failures return `500 Internal Server Error` with `{"error":"Failed to save URL"}`. If five generated codes in a row collide, the API returns `500` with `{"error":"Could not generate a unique short code"}`.

### List URLs

**Request**

```http
GET /api/urls
```

**Response — `200 OK`**

```json
{
  "count": 1,
  "urls": [
    {
      "longUrl": "https://www.example.com/",
      "shortCode": "a1b2c3d4",
      "shortUrl": "http://localhost:3000/a1b2c3d4",
      "clicks": 3,
      "createdAt": "2026-11-20T12:00:00.000Z"
    }
  ]
}
```

The database query orders records by `created_at` descending. A database failure returns `500 Internal Server Error` with `{"error":"Failed to retrieve URLs"}`.

### Delete a URL

**Request**

```http
DELETE /api/urls/a1b2c3d4
```

**Response — `200 OK`**

```json
{
  "message": "URL deleted successfully",
  "shortCode": "a1b2c3d4"
}
```

When the code does not exist, the API returns `404 Not Found`:

```json
{
  "error": "Short URL not found"
}
```

A database failure returns `500 Internal Server Error` with `{"error":"Failed to delete URL"}`.

### Redirect and track a click

**Request**

```http
GET /a1b2c3d4
```

For an existing code, the API increments its click count and responds with `302 Found`, redirecting to the original URL. The destination is sent in the `Location` header; there is no JSON success body.

An unknown code returns `404 Not Found`:

```json
{
  "error": "Short URL not found"
}
```

An error from the database function returns `500 Internal Server Error` with `{"error":"Failed to process short URL"}`.

## URL validation and code generation

The API accepts `longUrl` only when it is a non-empty string with no whitespace, can be parsed as a URL, uses `http:` or `https:`, has a hostname containing a dot, and does not include URL username or password credentials. The parsed URL's normalized `href` is stored. Invalid values return `400` with `{"error":"Invalid URL"}`.

For each creation attempt, the server generates four cryptographically random bytes and converts them to an eight-character hexadecimal short code. The `short_code` database column is unique. The API retries up to five times only when Supabase reports a unique-key conflict; a different database error is returned as a server error.

## Supabase database

The SQL in `schema.sql` creates `public.urls` with this structure:

| Column | Type | Constraints and default |
|---|---|---|
| `id` | `BIGINT` | Identity primary key |
| `long_url` | `TEXT` | Not null |
| `short_code` | `VARCHAR(20)` | Not null and unique |
| `clicks` | `INTEGER` | Not null; defaults to `0` |
| `created_at` | `TIMESTAMPTZ` | Not null; defaults to `NOW()` |

The schema enables Row Level Security and grants the `anon` role insert, select, and delete access to the table (and the required sequence permissions). It removes a legacy `user_id` column if present. No user/account ownership is implemented.

The `public.increment_url_clicks(p_short_code text)` SQL function updates the matching row's `clicks` value and returns its `long_url`. The redirect route calls this function through Supabase RPC; no matching row yields no destination, which the API reports as `404`.

## Error handling

The API returns JSON errors for URL validation, not-found cases, database operation failures, and caught unexpected errors. Database and unexpected errors are logged to the server console. The route-level fallback for an unexpected error is `500 Internal Server Error` with `{"error":"Internal server error"}`.

## Access considerations

The API does not authenticate callers, and the schema permits anonymous URL creation, listing, and deletion. Anyone with access to this API can therefore list or delete stored links. Do not treat this configuration as an access-controlled production deployment without adding appropriate protections.
